# GW 비서 디자인 원칙 (v0.76)

목적은 하나다. **디자인팀이 만든 제품처럼 보이고, 직원이 설명 없이 쓰는 화면.**
"세련되게"가 아니라 아래 다섯 가지를 지키는지로 판단한다. 새 화면을 만들거나 고칠 때 이 문서를 먼저 본다.

## 다섯 가지 원칙

1. **상자 대신 여백과 가는 선.** 테두리 있는 상자는 떠 있는 것(창·메뉴), 입력칸, 나란히 놓인 패널(`.card2`)뿐이다. 목록과 표는 상자에 넣지 않고 가는 선으로만 나눈다. 카드 안에 카드를 넣지 않는다.
2. **위계는 글자로.** 크기·굵기 세 단계(제목 24px/700, 본문 14~15px/500, 보조 12.5~13px/회색)만 쓴다. 색 배지는 예외를 알릴 때만 쓴다. 묶음 제목이 이미 "급한 일"이라고 말했으면 줄마다 "급함"을 되풀이하지 않고 점 하나로 줄인다.
3. **화면이 스스로를 설명하지 않는다.** 화면 제목 옆 부제는 상태·건수처럼 바뀌는 정보일 때만 둔다. 쓰는 법을 설명하는 문장은 빈 화면·오류처럼 필요한 순간에만 보인다. 문구에서 뜻에 보탬이 안 되는 낱말은 뺀다.
4. **색은 기관 표지의 짙은 청록 하나.** `--pri`(주된 버튼)와 `--accent`(고른 것·링크)는 로고에서 가져온 같은 계열이다. 빨강(`--hi`)은 급한 것에만 쓴다. 그 밖의 색은 상태(확인 필요 = 황토, 완료 = 초록)를 뜻할 때만.
5. **쓰지 않는 것.** 한쪽만 색칠한 테두리, 큰 숫자 타일, 같은 모양 카드 격자, 그라데이션, 기울인 배지, 장식용 아이콘 상자.

## 홈에 적용한 모습

- 맨 위는 인사가 아니라 **지금 상황 한 문장**("바로 처리할 일 5건이 있습니다")이다. 인사와 날짜는 그 위의 작은 글씨다.
- 그 아래 **먼저 할 일 한 가지**와 이어서 볼 일. 상자 없이 글자 크기로만 구분한다.
- 숫자는 타일이 아니라 **읽히는 한 줄**이다("급한 일 5 · 내가 처리·확인할 일 11 · …"). 누르면 그 목록으로 간다.
- 비서에게 묻기는 상자도 머리띠도 없이 입력칸만 면을 가진다. "맡길 수 있는 일" 카드 여섯 장은 없앴고 추천 질문 넉 줄이 그 일을 한다.
- 오른쪽은 오늘 일정과 챙겨 둘 것. 세로 선 하나로 나누고 묶음 사이는 가는 선이다.

## 확인하는 법

`npm run live:demo`로 둘러보기를 열어 밝게·어둡게 모두 본다. 실제 그룹웨어 화면에서의 확인은 따로 필요하다(둘러보기는 지어낸 자료다).

## 화면 뼈대 (v0.85)

- 12개 메뉴는 같은 순서로 시작한다: **제목(= 왼쪽 메뉴 이름) → 하위 탭 → 도구줄 → 본문**. 제목 자리에 달·사업명 같은 바뀌는 값을 두지 않고 도구줄로 보낸다.
- 목록은 한 건 한 줄(가는 선)이고 시각·동작 칸 폭을 고정해 줄마다 같은 자리에 둔다(통합알림, 할 일).
- 고정 색(#hex)은 쓰지 않는다. 강조면도 `--pri`/`--pri-fg` 토큰이라 다크 모드에서 위계가 유지된다.
- 글자 크기는 12/13/14/15 + 제목 단계만 쓴다(반 픽셀 단계 없음).
- 전역 '새로 만들기'는 테두리 버튼이다. 진한 버튼은 그 화면의 주 동작 하나뿐이다.


## 메뉴 체계 (v1.23)

비서의 목표는 그룹웨어에서 불편한 일을 직관적이고 간단하게 처리하거나 자동화하는 것이다. 가장 자주 쓰는 네 가지(할 일 관리, 일정·예약, 근태·연차, 예산 집행)를 기준으로 메뉴와 홈을 짠다.

1. **메뉴는 하는 일 단위.** 자료 출처(그룹웨어·구글·개인)로 메뉴나 탭을 나누지 않는다. 출처는 화면 안의 눌림 버튼(할 일의 전체·그룹웨어·개인, 달력의 그룹웨어·구글 캘린더)으로 거른다.
2. **한 기능은 한 화면.** 입구가 여러 개여도 같은 화면을 연다. 머리줄은 어디서나 하는 동작(검색·새로 만들기·AI 지시·알림), 왼쪽 메뉴는 장소다.
3. **핵심 4가 먼저.** 왼쪽 메뉴는 홈 · [핵심] 할 일 · 일정·예약 · 근태·연차 · 예산 집행 · [문서·소통] 결재·메일 · 찾기 · 보고 · 설정의 9개다. `VIEWS` 배열 순서가 Alt+1~9 순서다.
4. **화면마다 다음 단계 버튼.** 조회 → 준비(서식 채우기) → 확인 카드 → 사용자가 직접 제출. 예: 근태 화면의 신청 준비, 카드·세금계산서의 지출결의 준비, 달력 날짜의 자원 예약.
5. **건수는 출처별로 따로.** 합쳐 보여도 그룹웨어(`mineVisible`)와 개인 ToDo(`TD.list`)는 따로 세고, "조회분·확인된·확인 불가" 표시는 그대로 둔다.

| 메뉴 | 안의 탭·거르기 | 예전 화면 id (주소·비서 `open_view` 호환) |
|---|---|---|
| 할 일 | 목록 · 보드 / 출처: 전체 · 그룹웨어 · 개인 | today, mytodo, board |
| 일정·예약 | 달력(그룹웨어 · 구글 캘린더) · 자원 예약 | calendar, gcal, resource |
| 근태·연차 | 신청 준비(휴가 · 출장 · 시간외) | attendance |
| 예산 집행 | 내 사업(사업 상세는 그 안의 상세) · 카드·세금계산서 · 재단 전체 | budget |
| 결재·메일 | 결재·문서유통 · 메일 · 알림 | approval, mail, notifications |
| 찾기 | 통합검색 · 결재문서 · 사람·조직 | search, docs, people |
| 보고 | 보고서 · 현황 차트 | report, overview |
| 설정 | 설정 · 구글 연동 (자동화 관리 포함) | settings, gsync |

화면 id는 지우지 않고 `VIEW_PARENT`로 상위 메뉴에 묶는다. 화면 제목은 상위 메뉴 이름이다.

## 홈 (v1.23)

- 위에서 아래로: 날짜와 지금 상황 → **먼저 할 일 한 건**(그룹웨어 기한 지남·급함 → 개인 기한 지남 → 개인 오늘 마감 → 그룹웨어 나머지) → **오늘 현황**(핵심 4 줄). 오른쪽은 오늘 일정·자리 비움·챙겨 둘 것(놓치기 쉬운 일·안 읽은 메일·결재할 문서)·자원 예약.
- 오늘 현황은 상자 없는 4줄이다. 줄마다 요약 한 줄과 주 동작 하나(할 일 열기 · 예약하기 · 휴가 신청 준비 · 지출결의 준비)를 두고, 줄을 누르면 그 메뉴로 간다.
- 숫자는 홈에서 한 번만 나온다. 숫자 타일, '바로 시작' 버튼 묶음, 비어 있는 자동화 카드는 두지 않는다(자동화 관리는 설정).
- 예산 줄은 수집기가 이미 읽은 관심 사업 예산만 쓴다. 홈을 그릴 때 새로 조회하지 않는다.
- 비서 대화는 아직 사용성과 기능이 부족해 맨 아래에 둔다. 나아지면 자리를 다시 정한다.
