# 내 할 일 · 예산 집행 계획 설계 (v1.17)

2026-11-21 운영자 인터뷰를 바탕으로 정한 설계다. 인터뷰 답과 그룹웨어 실측을 근거로 삼는다.

## 1. 인터뷰 결과

| 질문 | 답 |
|---|---|
| 할 일 저장 위치 | 그룹웨어 ToDo 연동(세 PC·모바일 앱에서 같은 목록) |
| 할 일 기능 | 기한·중요도, 반복 업무, 체크리스트, 사업·예산 연결, 결재문서·메일 연결 (메모는 고르지 않았지만 그룹웨어 ToDo의 '내용' 칸이 있어 함께 제공) |

## 3. 저장 설계

진실의 원천은 그룹웨어 ToDo다. GW 비서는 화면을 빨리 그리려고 마지막 목록을 이 PC에 캐시만 한다.

| 기능 | 그룹웨어 칸 |
|---|---|
| 제목 | `todoName` (100자) |
| 기한 | `endDate` (시작일이 없으면 같은 날로 채움) |
| 중요 | `importDegree` 1/0 |
| 체크리스트 | 하위 ToDo |
| 완료 | `prj001A07` 진행률 100 |
| 메모 | `contents` 앞부분 |
| 반복·사업·예산·연결 문서 | `contents` 끝의 "GW 비서 정보" 묶음 |

`contents` 형식:

```
(사용자 메모)

— GW 비서 정보(이 아래는 고치지 마세요) —
반복: 매주 월요일
예산: 노121 회의비 300,000원 (12/5 예정)
연결: 전략경영실-8415
⟦gwb:{"v":1,...}⟧
```

사람이 읽는 줄은 매번 다시 만든다. 기계는 마지막 `⟦gwb:…⟧`만 읽는다. 그룹웨어나 모바일에서 메모를 고쳐도 표시줄 위쪽만 메모로 읽으므로 정보가 깨지지 않는다. 묶음이 깨져 JSON을 읽지 못하면 부가 정보 없이 일반 할 일로 다룬다(지우지 않음).

## 4. 반복 업무

- 규칙: 매일(평일), 매주 요일(여러 개), 매월 N일, 매월 말일. 주말·휴일에 걸리면 그 앞 평일로 당긴다(매일 평일 규칙은 다음 평일).
- 완료하면 같은 묶음 번호(`sid`)로 다음 회차를 만든다. 다른 PC나 모바일에서 완료한 경우에도 다음 동기화 때 만든다.
- 중복 방지: 다음 회차를 만들기 직전에 목록을 다시 읽어 같은 `sid`의 열린 회차가 있으면 만들지 않는다. 만든 뒤 이전 회차의 정보에 `nx`(다음 회차 번호)를 적는다.

## 5. 예산 집행 계획

계획 한 건 = 예산 정보가 붙은 할 일 한 건("12/5 자문회의 회의비 결의"). 할 일 목록과 예산 화면 양쪽에 보인다.

- 정보: 사업(`A201`), 항(`노121`), 세목 코드(`노1211211`), 금액, 예정일, 근거 계획서 문서번호, 짝지은 결의 내역.
- 상태: 계획 → (짝 확인) → 집행됨. 일부만 집행되면 남은 금액이 계속 계획으로 남는다. 남은 금액을 포기하면 계획 금액을 집행액으로 줄이고 끝낸다.

### 예상 집행률

세목마다

- 집행액 E = 예실대비 누계 집행액(조회값)
- 남은 계획 P = Σ(계획 금액 − 짝지은 결의 금액), 단 짝 확인을 기다리는 결의 금액은 빼서 이중 계산하지 않음
- 예상 = E + P, 예상 집행률 = 예상 ÷ 예산

항 전체는 세목 합. 목표 100%와의 차이 = 예산 × 목표 − 예상(양수면 "아직 계획이 없는 돈", 음수면 "예산보다 많게 계획").
경고: 세목별 계획 초과, 예정일이 지났는데 결의가 없는 계획, 회계 마감일(기본 12/31) 뒤로 잡힌 계획.

### 자동 짝짓기

계획마다 같은 세목의 결의 내역 중 다른 계획이 이미 가져가지 않은 행만 본다. 결의일이 계획을 만든 날(근거 계획서가 있으면 그 결재일) 3일 전보다 앞서면 제외한다.

점수: 금액이 남은 금액과 같음 +3, 남은 금액 이하 +1, 적요와 제목·계획서 제목의 공통 낱말 1개당 +1(최대 3), 예정일 ±14일 +1. 3점 이상만 제안한다. 같은 낱말을 가진 여러 행을 합쳐 남은 금액 이하가 되면 묶음으로 제안한다. 확정은 사용자가 누른다.

### 내 계획서에서 가져오기

GW 비서가 학습한 내 결재문서 중 올해 '…계획'의 "소요예산: 금…원"과 "예산과목: … 부기)…"를 읽는다. 부기 이름을 담당 항의 세목 이름과 맞춘다(공백·가운뎃점·○ 무시). 이미 결의된 금액(위 짝짓기 규칙으로 찾은 결의)을 빼고 남은 금액이 있는 계획서만 후보로 보인다. 세목이 여러 개면 사용자가 나눈다(기본은 첫 세목에 전액).

## 7. 안전

- 쓰기 허용 목록에 ToDo 네 주소를 더한다. 쓰기는 전용 함수에서만 하고, 고치기·완료·지우기 전에 상세를 읽어 내가 담당자이자 만든 사람인 개인 ToDo(`prjSeq` 없음)인지 확인한다.
- 지우기는 화면에서 확인 창을 거친다. AI가 고른 내용으로는 만들기·지우기를 하지 않는다(대화의 "할 일 추가: …"처럼 사용자가 직접 쓴 문장만).
- ToDo 목록 읽기는 열람 기록을 남기지 않는다(그룹웨어 화면도 같은 주소를 부른다).
- 이 PC에만 있던 예전 할 일은 사용자가 [그룹웨어 ToDo로 옮기기]를 눌러야 옮긴다.

독립 검토(읽기 전용 검토 에이전트)에서 나온 P0 2건·P1 11건을 모두 고쳤다: '메모' 낱말만으로 ToDo 생성, 계획서 가져오기 칸 번호 어긋남, 캐시의 잘린 메모 되쓰기, 정보 묶음 뒤 덧붙인 글 유실, 읽는 중 강제 새로 읽기, 지우기 도중 실패, 옮기기 중복, 연결 전 로컬 할 일 유실, 다른 사업 같은 세목 코드, 날짜 말 해석, 예전 회차에서 다시 만들기·늦게 끝낸 회차, 지난해 계획. 그 밖에 여러 PC 동시 생성 방지(만드는 중 표시), 다른 곳에서 바뀐 내용 덮어쓰기 방지, 다른 사람이 준 ToDo 읽기 전용, 조회 경로의 쓰기 제외도 넣었다. 실화면 점검에서 상세 API에 중요도가 없어 고칠 때 '즉시'가 '일반'으로 바뀌던 문제를 찾아 고쳤다.

## 9. 확인하지 못한 것

- 모바일 앱에서의 표시 형태(그룹웨어 웹 ToDo 화면에서는 확인)
- 다른 PC(사무실·노트북)에서의 실제 동시 사용. 같은 서버 목록을 읽는 구조라 같은 목록이 보여야 하지만, 각 PC는 v1.17로 업데이트된 뒤 확인해야 한다
- 그룹웨어 '내용' 칸의 최대 길이(1,500자 넘으면 저장 전에 막음)
- 날짜 입력칸 끝의 '[]' 모양은 이 브라우저의 날짜 칸 표시로, GW 비서 밖의 빈 날짜 칸에서도 같다(기존 화면 포함)

## 9. 그룹웨어 ToDo와 동등 + 우월 (v1.20, 2026-11-22)

운영자 요청: "기존 그룹웨어와 비서의 할 일 기능·품질 차이가 너무 크다. 동등하면서 우월해야 한다." 그룹웨어 업무관리(개인 업무) 화면 코드와 실제 응답을 읽어 차이를 정리하고 메웠다.

| 그룹웨어 기능 | v1.19 비서 | v1.20 비서 |
