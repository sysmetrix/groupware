# 로그인 화면 조회 자료 연결

2026-10-23 사용자가 지정한 오른쪽 앱 내 브라우저에서 로그인 후 정상 화면 조회가 가능해졌다. 전자결재 대기문서, 일정 목록, 공지사항 목록 및 공지 상세 한 건을 실제로 확인했다. 기존 ego lite 작업 공간 문제와 별개로 이번 사용자가 선택한 브라우저에서는 조회가 성공했다.

## 현재 제공하는 범위

- `browser-snapshot`은 정상 로그인 화면을 읽어 가져온 시점의 사본이다. 상시 수집이나 서버 API 연결을 의미하지 않으며 `liveConnected`는 false다.
- 결재 대기: 모든문서 필터에서 명시적인 0건 및 빈 목록을 확인했다. 결재 HOME의 완료 문서를 대기로 분류하지 않는다.
- 일정: 2026년 10월 목록, 전체 보기, 화면에서 선택 표시를 확인한 개인·공유 캘린더 범위에 빈 결과가 표시됐다. 다른 기간과 캘린더까지 비어 있다고 일반화하지 않는다.
- 공지: 전체 2,507건 중 첫 페이지 일반 공지 10건. 번호 없는 상단 고정 글은 제외했다. 본문은 한 건만 읽었으며 나머지는 제목·화면 날짜만 제공한다.
- 규정·서식과 첨부는 미조회다. 공지 내용은 규정으로 분류하지 않는다. 검색은 접근 가능한 published 문서와 공지에서 수행한다.

업무 자료와 로그인 사용자는 `data/browser-capture/`에만 저장한다. 공개 문서나 테스트에 실제 제목·본문·사용자 이름을 넣지 않는다. 쿠키·토큰·비밀번호·브라우저 내부 상태는 수집하지 않는다. 상세를 여는 정상 조회는 원 사이트의 조회수·읽음 상태에 영향을 줄 수 있다.

## 검색 범위와 빈 결과

검색 화면은 직접 넣은 문서와 가져온 자료의 건수를 각각 표시한다. 내 문서가 0개이면 검색·AI 요청을 보내지 않고 파일 추가 또는 실제 수집 자료로 전환하도록 안내한다. 수집 자료의 결과 없음은 그룹웨어 전체에 해당 문서가 없다는 뜻이 아니다. 2026-10-23 빈 자료, 수집 범위 내 결과 없음, 실제 공지 검색 성공을 앱 내 브라우저에서 확인했다. AI가 꺼진 상태의 검색 검증이며 AI 요약 품질 검증을 의미하지 않는다.

## 데이터 계약

기존 dataset 계약에 `source.kind: "browser-snapshot"`와 `source.coverage`를 추가했다. coverage는 approval, schedule, notice, document 네 유형을 중복 없이 포함한다.

각 항목은 `type`, `state` (complete / partial / unobserved), `query`, `collected`, `total`, `url`이다. complete는 **query에 명시한 범위만** 완료이며 total과 collected가 같아야 한다. unobserved는 collected=0, total=null이다. partial은 총계가 불명확하면 total=null을 허용한다. URL은 출처와 같은 origin이며 인증값이 없어야 한다.

사용자·조직의 로컬 연결 식별자는 실제 제품의 서버 ID가 아니다. `buildBrowserSnapshot`은 별도 기대 principal과의 정확한 일치 및 현재 사용자 한 명의 ACL을 검사한다. 이는 서버 ACL의 독립 검증이나 새 세션의 인증을 대체하지 않는다.

목록 번호는 이 조회 범위의 로컬 레코드 식별에만 사용한다. 원문 고유 ID·상세 링크는 추측하지 않는다. `조회화면링크` 태그가 있는 링크는 UI에 ‘그룹웨어 조회 화면’으로 표시한다. 목록에 연도가 없는 날짜는 원문 갱신시각으로 추정하지 않고 본문 설명에 원문 문자열을 보존한다. 해당 레코드 updatedAt은 조회 시각이며 이를 본문에 명시한다.

## 가져오기

```powershell
node scripts/import-browser-snapshot.mjs data/browser-capture/dataset.json data/browser-capture/principal.json http://127.0.0.1:3210
```

이 명령은 브라우저를 새로 조회하지 않는다. 검증된 캡처 JSON을 실행 중인 로컬 앱으로 보내며 외부 서버에 전송하지 않는다. 기대 principal 파일과 불일치, 다른 범위의 실제 자료, 더 오래된 사본은 거부한다. 첫 실행은 합성 예제를 실제 사본으로 교체한다. UI의 브리핑 새로고침도 저장된 사본을 재계산한다.

## 남은 자동 수집 단계

브라우저 조회 → 사본 생성 → 로컬 앱 반영은 이번 세션에서 실행했다. 현재 수집은 에이전트가 제어하는 로그인 세션에 의존한다. 별도 PC에서 독립적으로 실행되는 브라우저 커넥터, 세션 만료·사용자 전환 탐지, 공지 전체 페이지/삭제 대조, 일정의 실제 항목 수집, 원문 상세 ID, 첨부, 초안 저장은 아직 검증되지 않았다. 이 항목을 완료하기 전 상시 자동 연결이나 전체 구현 완료로 표시하지 않는다.
