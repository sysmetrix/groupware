# 검증 기록과 수동 절차

## 자동 검사

`npm run check`는 소스·프런트엔드·테스트의 JavaScript 문법을 검사한다. `npm test`는 Node 내장 러너로 다음을 검증한다.

- 사용자·조직 필터 및 빈 ACL의 접근 거부
- 완료 결재 제외, 기한 경과, 한국시간 날짜 경계
- 진행 중 일정 포함, 종료·취소·완료 일정 및 7일 경계 제외
- 만료·미시행 문서 제외, 근거 없음 응답
- 중복 ID·민감 추가 필드·잘못된 날짜·위험한 링크 거부
- 금액 형식·정확한 금액 대조·필수 입력·첨부 미확인
- 모델 요청의 제한된 근거, 모의 응답의 출처 ID 검증, 모델 실패
- 실제 loopback HTTP 서버의 정적 파일·작업·가져오기·실행 기록
- CSRF·교차 출처 요청 차단, 잘못된 JSON과 content type
- 검색어·문서 본문을 감사 기록에 남기지 않음
- CSV/TSV 인용·개행·머리글·타입·출처 검사
- 자동 파일 확인의 사용자·조직·시각 검사, 오류 시 기존 스냅샷 보존
- 한국 시간 정기 브리핑, 날짜 변경, 중복·동시 실행, 재시작 후 보고서 복원
- 자료가 바뀌거나 만료되면 이전 보고서 제공 거부

로컬 Node 24/Windows에서 자동 테스트를 수행했다. GitHub Actions 설정은 Ubuntu/Windows를 대상으로 한다. 실제 LLM 설치·추론, 그룹웨어 실시간 연결, 브라우저 렌더링은 자동 테스트 범위에 포함되지 않는다.

## 브라우저 검증 상태

Windows Computer Use가 현재 브라우저 URL을 충분히 확실하게 판별하지 못해 중단됐다. 시각 검증 완료나 브라우저 E2E 통과를 주장하지 않는다. 다음 항목은 릴리스 전 남은 점검이다.

1. `npm start` 후 `http://127.0.0.1:3210` 접속. 합성 예제/실시간 미연결 표시와 4개 현황 카드 확인.
2. 브리핑 새로고침 후 원문 없는 예제가 허위 링크를 표시하지 않는지 확인.
3. 문서 검색에서 `운영계획` 입력. 유효한 예제 문서가 보이고 만료 예제가 제외되는지 확인.
4. `찾을수없는키워드`를 검색해 근거 없음 확인.
5. 초안에서 본문 1,000원·첨부 900원을 입력하고 100원 불일치 확인. 숫자/날짜 오류 확인.
6. 예제 JSON 다운로드, 데이터 교체 확인란, 가져오기 성공·오류 확인. 실제 자료를 테스트에 사용하지 않음.
7. 실행 기록에 작업만 남고 입력한 본문·검색어가 없는지 확인.
8. 390px·768px·1440px 화면, 키보드 Tab, 포커스 표시, 한국어 줄바꿈 확인.
9. 로컬 모델을 별도 설정한 환경에서 요약과 원문 출처를 대조하고, 모델 중단 시 근거만 유지되는지 확인.

## 운영 전 조건

실제 그룹웨어 연동의 권한·페이지 완전성·문서 버전·조회 부작용은 `live-integration.md`를 따라 검증한다. 로컬 스냅샷 파일의 ACL 값은 서버 권한 검증의 대체 수단이 아니다.

다른 PC 설치·업데이트 스크립트는 기존 설정을 보존하도록 설계했다. Windows 작업 스케줄러 스크립트는 구문만 검사했으며 실제 등록·로그인 실행을 검증한 것으로 표시하지 않는다. 브라우저 TaskSpace가 재접속 시 존재하지 않는 오류가 반복되어 실제 조회 연결 확인은 중단 상태다.
