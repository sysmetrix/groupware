GROUPWARE ASSISTANT / REFERENCE REVIEW

그룹웨어 자동화의 다음 단계공식 레퍼런스 비교 · 적용한 개선 · 후속 검증 기준

현재 파일 기반 업무 도우미의 복구와 자료 최신성을 먼저 개선했습니다. 실제 업무 시스템과 연결하기 위한 수집 완전성·권한 회수·중복 실행 방지는 별도 설계로 정리했습니다.

조사·구현 기준일 2026-10-23 · 자동화 문서 7종 + 제품 자료 2종 + 첨부 형식 자료 3종 · 로컬 Node 24 / Windows · 공개 배포용

01 / DECISION무엇을 적용했는가

7개 문서Microsoft · Temporal · n8n · OWASP 공식 자료
82개 테스트Node 73개 + Python 9개
파일 자동화실시간 조회·업무 변경 커넥터는 미구현

현재 규모에서는 기존 Node.js 실행기를 유지하고 오류 분류·확인 간격 조절·재시작 재검증을 적용하는 편이 적절하다고 판단했습니다. 외부 워크플로 엔진 설치·운영이 꼭 필요한지는 장시간 승인 대기, 다중 작업자, 외부 시스템 연동 요구가 구체화된 뒤 평가합니다. 이는 이번 프로젝트에 대한 설계 판단입니다.

아래는 다른 플랫폼의 공식 설계 문서를 분석한 결과입니다. Amaranth 10의 API·이벤트·서비스 계정 지원 여부나 기관의 계약을 확인한 자료가 아닙니다. 실제 그룹웨어 운영 자동화가 완성되었다는 뜻도 아닙니다.

방법: 공식 문서 검색 → 해당 페이지 본문 확인 → 현재 코드의 차이 확인 → 필요한 패턴만 구현 → 장애 주입·재시작 테스트. 운영 구축 사례의 성과나 비용 절감률은 검증하지 않았습니다. 제한된 공개 검색만으로 제품 API가 없다고 판정하지 않았습니다.

02 / REFERENCES출처와 적용 판단

공식 출처확인한 내용현재 코드에 대한 판단반영 범위
R1 · Microsoft Graph
Delta query		추가·수정·삭제 추적. 빈 결과에도 nextLink가 있을 수 있고, 페이지 순회를 완료해야 deltaLink를 얻음.부분 목록을 전체 자료로 교체하지 않고, 수집 확정 뒤 체크포인트를 저장하도록 설계.기반 구현
정규화 페이지 전체·증분 수집 구현. 실제 API 어댑터는 미구현.
R2 · Microsoft Graph
Throttling		429에서 즉시 반복하지 않고 Retry-After를 따름. 헤더가 없을 때 지수형 대기를 권고.재시도 정책과 오류 유형을 분리. 현재는 로컬 파일 오류에 대기 간격 조절만 적용.부분 적용
HTTP 429·Retry-After 처리는 미구현.
R3 · Temporal
Retry policies		초기 간격·증가 계수·최대 간격·재시도 제외 오류를 구분하는 정책. 실패 가능한 작업을 분리.일시적 IO 오류와 잘못된 입력·권한·저장 공간 문제에 서로 다른 복구 안내와 간격 적용.적용
자체 파일 실행기에 반영. Temporal 도입은 아님.
R4 · Temporal 공식 문서 소스
Idempotent activities		성공 통지 전 작업자 중단으로 작업이 다시 실행될 수 있으므로 중복 실행에 견디도록 설계.기존 해시 기반 중복 보고서 억제에 재시작 검증을 추가. 미래 변경 작업에는 원문 결과 확인과 서버의 중복 방지 계약 필요.부분 적용
로컬 중복 억제는 exactly-once 보장이 아님.
R5 · n8n
Error workflows		실패 실행을 조사하고 Error Trigger로 오류 처리 흐름을 별도 구성. 여러 흐름에서 공통 처리 가능.오류 코드를 구조화하고 실행 ID·사용자 복구 안내를 연결. 같은 실패의 반복 로그를 억제.적용
로컬 상태·감사 기록에 반영. 외부 알림 발송 없음.
R6 · Power Automate
Desktop flow errors		설계·실행 시점 오류와 작업·블록 단위 오류 처리 및 재시도 설정을 구분.입력 수정이 필요한 오류와 일시 파일 오류를 구분. 단계별 복구 절차를 문서화.적용
브라우저 제어 해제나 권한 오류를 자동 우회하는 방식으로 사용하지 않음.
R7 · OWASP
Prompt injection prevention		외부 문서의 간접 지시, 최소 권한, 출력 검증, 중요 작업의 사람 검토를 다룸.문서 텍스트를 명령으로 실행하지 않는 기존 경계를 유지. 모델에 도구·인증값을 제공하지 않음.기존 설계 확인
JSON·출처 ID 검사는 의미적 사실 검증이나 완전한 공격 방어가 아님.

출처는 2026-10-22에 확인한 공개 문서이며 변경될 수 있습니다. R4는 공식 저장소의 문서 원본입니다. 모든 패턴을 동일 제품의 실제 지원 기능으로 해석하지 않습니다.

03 / IMPLEMENTED이번에 바뀐 실제 동작

상황이전변경 후
일시 파일 잠금고정 간격 확인, 포괄적 오류 표시일시 IO 오류를 분류하고 대기 증가. 기본 60초 설정은 실패 후 120 → 240 → 480 → 900초. 성공 시 원래 주기 복귀.
잘못된 사용자·조직·시각오류 문구는 있었으나 구조화된 복구 상태가 없음오류 코드·복구 안내·연속 실패 수·다음 확인 시각 제공. 수정된 입력을 찾기 위한 기본 주기 유지.
프로세스 재시작저장된 자료와 보고서가 일치하면 현재 입력 확인 전에도 보고서 제공 가능이번 프로세스에서 입력 파일을 성공적으로 확인할 때까지 보고서 다운로드 보류. 입력 누락·손상 시 계속 보류.
현재보다 과거인 내보내기유효 시간 범위 안이면 최신 자료를 덮어쓸 수 있음동일 사용자·조직·출처의 과거 exportedAt을 거부. 재시작 뒤에도 저장된 자료 기준으로 검사.
정기 작업이 오래 걸림고정 타이머가 실행 중에도 호출실행 종료 후 다음 타이머 예약. 실행 중 중지·재시작에도 다음 타이머는 하나.
보고서 생성·실패 조사작업·시각·결과 중심실행 ID와 오류 코드 추가. 같은 오류가 이어질 때 중복 실패 기록 억제. 임의 오류 원문·본문은 기록 제외.
1. 검증형식·범위·신선도·시간 역행2. 반영해시 비교·전체 자료 교체3. 보고당일·최신 스냅샷·완료 기록4. 재확인성공은 기본 주기
일시 오류는 대기 증가

수동 실행은 대기를 생략하되 진행 중인 실행은 공유합니다. 다음 자동 확인까지 입력 파일 변경을 감지하지 못하는 구간은 남습니다. 보고서·감사 파일을 하나의 트랜잭션으로 저장하지 않으므로 프로세스 중단 시 누락 기록 복원이나 정확히 한 번 실행을 보장하지 않습니다.

구현: src/recovery.mjs, src/automation.mjs, src/store.mjs, public/app.js. 운영 조치는 오류 코드와 복구 절차를 참고하세요.

04 / DESIGN실제 연동 전에 필요한 계약

아래는 실제 제품 연동의 요구 조건입니다. 페이지 완전성·삭제·권한 회수는 정규화 입력 모듈로 구현했고, 실제 API·서버 권한·변경 실행은 남아 있습니다. 수집 URL이나 데이터 필드를 추측해 호출하지 않습니다.

설계 대상요구 동작반드시 재현할 실패
완전한 조회페이지를 임시 수집하고 마지막 페이지·중복·건수 검증 후 게시. 자료 확정 후에만 체크포인트 이동.빈 중간 페이지, 마지막 페이지 실패, 중복 페이지, 잘못된 전체 건수
권한과 삭제사용자·조직·조회 조건을 동기화 상태에 묶음. 권한 회수·삭제를 검색·요약·첨부에도 반영.계정 전환, 403, 문서 삭제, 토큰 무효, 오래된 요약 재노출
외부 요청 복구계약상 지원하는 대기 지시를 우선. 세션 만료는 인증 복구로 분리. 브라우저 제어 해제는 중단.429, 타임아웃, 연결 중단, 만료된 세션
업무 변경계획·검토·승인 범위·최신 상태 재조회·서버 중복 방지·결과 확인을 연결.성공 후 응답 유실, 이중 클릭, 문서 버전 충돌, 승인 만료
AI 근거 평가문장별 원문 위치·버전 연결. 허용된 자료 표본으로 근거 충족과 수정량 평가.문서 속 실행 지시, 유효 ID를 붙인 허위 주장, 근거 없는 답변

n8n은 외부 연결과 오류 흐름이 많아질 때, Temporal은 장시간 작업 복구·작업자 분산이 필요할 때 평가할 후보입니다. Power Automate는 데스크톱 연동을 검토할 후보입니다. 이번에 이 도구들을 설치하거나 비용·라이선스·조직 적합성을 비교 검증하지 않았습니다.

08 / ATTACHMENTS첨부 문서 추출과 위치가 있는 검색 근거

XLSX시트명·셀 주소셀 원시값, 수식은 식 자체만 표시. 수식 계산·날짜/통화 서식 복원 없음. 숨긴 시트 제외.

추출 파일 SHA-256, 원문 버전·갱신 시각, 추출 시각과 경고를 저장합니다. 원문 버전/시각이 달라지면 가져오기를 거부합니다. 부모 문서의 조직·사용자·게시 상태·시행 기간을 먼저 필터링하고, 삭제·권한 회수가 입력에 반영되면 첨부 근거도 검색에서 제외합니다. 첨부 자체의 서버 권한과 소속은 자동 검증하지 않습니다.

다른 PC에서 실행

기본 앱은 Node 24로 실행합니다. 첨부 기능만 Python 환경과 requirements-attachments.txt를 추가 설치하고 ATTACHMENT_PYTHON에 해당 PC의 실행 파일을 지정합니다. 원본 자료와 추출 JSON은 Git 제외 폴더 data/에 보관합니다.

출력 JSON을 데이터 연결에서 가져옵니다. CLI 실행만으로 현재 앱 자료가 교체되지는 않습니다. 검색 결과와 AI 인용에 위치·경고가 표시되며 원문 링크는 부모 문서로 연결됩니다.

  • Microsoft Open XML 셀 읽기: 공유 문자열·셀 형식과 위치를 구분했습니다.
  • pypdf 텍스트 추출: 텍스트 레이어 추출과 OCR·메모리 한계를 구분했습니다.
