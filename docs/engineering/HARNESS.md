# 개발 하네스 · 루프 · 코드 그래프

목표: 사람이든 AI 에이전트든 "고치고, 바로 확인하고, 깨진 것만 다시 고치는" 순환을 빠르고 안전하게 돌린다.

## 1. 하네스 (검증 묶음)

| 명령 | 용도 | 시간 |
|---|---|---|
| `npm run harness:fast` | 구문 + 코드 그래프 + 핵심 테스트 | 약 2초 |
| `npm run harness` | 위 + 전체 테스트 + 빌드 + 예산 + 안전 규칙 + 비밀 점검 | 약 1분 |
| `node scripts/harness.mjs --json` | 기계가 읽는 결과(에이전트용) | |
| `npm run e2e` | 핵심 여정 다섯 가지를 실제 브라우저에서 확인(전체 하네스에 포함) | 약 25초 |
| `npm run eval:chat` | 대화 평가 문항 채점(단위 테스트에 포함) | 1초 |

결과는 `build/harness/report.md`, `report.json`에 남는다. 실패가 하나라도 있으면 종료 코드 1.

단계와 잡는 것:
1. **구문 검사** GW 비서 조각, 수집기, 빌드 스크립트 전체.
2. **코드 그래프** `R.`(briefing.mjs) / `GW.`(수집기) 계약 위반, 미정의 함수 호출, 처리기 없는 `data-act`. 이 세 가지는 실행 중에야 터지는 오류라 가장 값어치가 높다.
3. **단위 테스트** 순수 함수(날짜, 금액, 근태 판정, 감사 해시 등)와 화면 이벤트 계약.
4. **핵심 여정** 둘러보기를 설치된 Chrome·Edge에 창 없이 띄우고 `scripts/journeys.browser.js`를 돌린다. 홈 확인 뒤 결재 처리, 근태 신청 준비, 결과보고 기안, 예산 집행 조회, 비서에게 묻기를 누르고 입력해 화면에 보이는 것으로 확인한다. 브라우저가 없으면 주의로만 남기고, CI에서는 실패로 처리한다.
5. **빌드와 예산** 번들 1120KB 이하(빌드가 한 줄 전체 주석을 빈 줄로 바꿔 줄인다. 상한은 `scripts/live-build.mjs`의 `MAX_SHIPPED_BUNDLE_BYTES`), 조각 파일 하나 600줄 이하 권장, 버전(GW 비서/수집기/확장) 일치.
6. **안전 규칙** 읽기 전용 주소 목록에 쓰기로 보이는 주소 금지, 비가역 버튼 차단 목록(상신, 결재, 임시저장, 삭제, 발송) 유지, 기록기 재생 확인 정책 유지, 허용 외 외부 주소 경고, 글자 12px 미만 금지(wc.css 포함).
7. **비밀·개인정보** 추적 파일에 수집 원본/.env/토큰/키/주민번호 형태가 없는지.

알려진 환경 문제로 실패하는 테스트는 `scripts/harness-known.json`에 이유와 함께 격리한다(실패가 아닌 주의로 보고). 원인을 고치면 항목을 지운다.

## 2. 루프 (고치고 바로 확인)

- 사람: `npm run loop` 를 켜 두면 파일을 저장할 때마다 `harness:fast`가 돌고 "새로 깨짐 / 해결"만 출력한다.
- 에이전트: 수정 후 `npm run loop:once` 를 호출한다. 직전 실행 대비 변화만 나오므로 출력이 짧다.

에이전트 작업 규칙(권장):
1. 시작 전 `loop:once`로 기준선을 잡는다.
2. 수정 -> `loop:once` -> 새로 깨진 항목이 있으면 그것만 고친다. 같은 항목을 3번 고쳐도 안 풀리면 접근을 바꾼다.
3. 마무리 전 `npm run harness` 전체 통과 + 실화면 스모크 통과를 확인한다.
4. 푸시 전 훅(`.githooks/pre-push`)이 전체 하네스를 자동 실행한다. 새 PC에서는 `git config core.hooksPath .githooks` 한 번.

## 3. 실화면 스모크 (그룹웨어 탭에서 실행)

`scripts/live-smoke.browser.js`: 모든 메뉴 화면 전환, 오버레이 열기/닫기, 값 이상("undefined", "NaN", "[object Object]") 검사, 12px 미만 글자, 가로 넘침, GW 비서 안에 상신/결재/삭제 버튼이 없는지, 최근 앱 오류. 읽기 전용이다. 실행법은 파일 머리말 참고(백그라운드 시작 후 `window.__smoke` 폴링).

### 둘러보기로 눈으로 확인

`npm run live:demo` → <http://127.0.0.1:3220>. 그룹웨어 로그인 없이 지어낸 자료로 모든 메뉴를 띄운다. 화면·CSS를 고쳤으면 밝게·어둡게와 좁은 창(약 760px)까지 여기서 확인한다. 실제 그룹웨어 동작(원래 화면 열기, 첨부 받기)은 확인되지 않으므로 실화면 스모크를 대신하지 않는다.

## 3-1. 핵심 여정과 대화 평가

- **핵심 여정**(`npm run e2e`)은 패키지를 설치하지 않는다. `scripts/e2e.mjs`가 설치된 브라우저를 찾아 DevTools 프로토콜로 직접 조종한다. 다른 브라우저는 `BROWSER_PATH`로 지정하고, 눈으로 보려면 `node scripts/e2e.mjs --headed`. 지어낸 자료로 도는 검사라 실제 그룹웨어 동작은 증명하지 않는다.
- 여정에 단계를 더할 때는 사람이 보는 것(글자, 버튼, 카드)으로 확인하고 내부 상태를 들여다보지 않는다. 확인 카드는 누르지 않는다.
- **대화 평가**(`eval/chat-questions.json`)는 "이 말에는 이 일이 일어나야 한다"를 사용자 입장에서 적은 문항이다. 대화 규칙(`src/live/chat.mjs`)을 고치면 `npm run eval:chat`을 돌린다. 새로 틀린 문항이 있으면 실패한다. 당장 못 고치는 문항은 `known: true`로 적어 두고, 고쳐지면 채점기가 지우라고 알려 준다. 문항의 답을 규칙에 맞춰 바꾸지 않는다.
- 실제로 쓰다가 비서가 잘못 알아들은 말은 문항으로 옮겨 적는다. 지금 문항은 지어낸 것이라 실제 말투를 다 담지 못한다.
- AI(Gemini)가 고른 도구의 채점은 아직 없다. 실제 키가 필요하다.

## 4. 코드 그래프

- `npm run graph` 의심 목록, `npm run graph:write` 로 `docs/engineering/code-graph.md`(Mermaid 모듈 의존, 이벤트->함수 그래프) 갱신.
- 용도: 어디를 고치면 어디가 영향받는지 보기, 쓰이지 않는 처리기/죽은 코드 정리 후보 찾기, 모듈이 한쪽으로 쏠리는지 점검.
- 한계: 정밀 파서가 아니다. 문자열/주석을 지운 뒤 식별자를 읽는 방식이라 "의심 목록"이다. 동적으로 만든 함수 이름은 못 본다.

## 5. 구조 규칙

작업 레벨별 모델·난도와 앞으로의 작업 순서는 [평가와 지향점](direction.md)에 있다.


- 순수 판정 로직은 `src/live/briefing.mjs`나 그 뒤에 이어 붙는 모듈(`home-model`, `chat`, `gcal-sync`, `settings-transfer`, `doc-find`, `usage`, `contract`, `changelog`)에 두고 테스트를 붙인다(화면 코드에는 계산을 두지 않는다).
- 이어 붙는 모듈을 새로 만들면 세 곳에 등록한다: `scripts/live-build.mjs`의 `EXTRA_MODULES`, `scripts/lib/wc-analyze.mjs`의 목록, `scripts/harness.mjs`의 `liveFiles`. 하나라도 빠지면 코드 그래프가 `R.이름 없음`으로 알려 준다.
- 업데이트 내역은 `src/live/changelog.mjs`에 있다. 손으로 고치지 않고 `npm run bump`로 추가한다.
- 화면 조각(`src/live/wc/NN-*.js`)은 파일명 순으로 이어 붙는다. 새 `data-act`를 만들면 `16-events.js`에 `case`를 같이 만든다(하네스가 검사).
- 비가역 동작은 코드로 차단하고, 새 외부 주소는 허용 목록에 이유와 함께 추가한다.
