# 개발 하네스 · 루프 · 코드 그래프

목표: 사람이든 AI 에이전트든 "고치고, 바로 확인하고, 깨진 것만 다시 고치는" 순환을 빠르고 안전하게 돌린다.

## 1. 하네스 (검증 묶음)

| 명령 | 용도 | 시간 |
|---|---|---|
| `npm run harness:fast` | 구문 + 코드 그래프 + 핵심 테스트 | 약 2초 |
| `npm run harness` | 위 + 전체 테스트 + 빌드 + 예산 + 안전 규칙 + 비밀 점검 | 약 1분 |
| `node scripts/harness.mjs --json` | 기계가 읽는 결과(에이전트용) | |

결과는 `build/harness/report.md`, `report.json`에 남는다. 실패가 하나라도 있으면 종료 코드 1.

단계와 잡는 것:
1. **구문 검사** GW 비서 조각, 수집기, 빌드 스크립트 전체.
2. **코드 그래프** `R.`(briefing.mjs) / `GW.`(수집기) 계약 위반, 미정의 함수 호출, 처리기 없는 `data-act`. 이 세 가지는 실행 중에야 터지는 오류라 가장 값어치가 높다.
3. **단위 테스트** 순수 함수(날짜, 금액, 근태 판정, 감사 해시 등)와 화면 이벤트 계약.
4. **빌드와 예산** 번들 900KB 이하(빌드가 한 줄 전체 주석을 빈 줄로 바꿔 줄인다), GW 비서 1200줄 이하 권장, 버전(GW 비서/수집기/확장) 일치.
5. **안전 규칙** 읽기 전용 주소 목록에 쓰기로 보이는 주소 금지, 비가역 버튼 차단 목록(상신, 결재, 임시저장, 삭제, 발송) 유지, 기록기 재생 확인 정책 유지, 허용 외 외부 주소 경고, 글자 12px 미만 금지(wc-premium.css 포함).
6. **비밀·개인정보** 추적 파일에 수집 원본/.env/토큰/키/주민번호 형태가 없는지.

알려진 환경 문제로 실패하는 테스트는 `scripts/harness-known.json`에 이유와 함께 격리한다(실패가 아닌 주의로 보고). 원인을 고치면 항목을 지운다.

## 2. 루프 (고치고 바로 확인)

- 사람: `npm run loop` 를 켜 두면 파일을 저장할 때마다 `harness:fast`가 돌고 "새로 깨짐 / 해결"만 출력한다.
- 에이전트: 수정 후 `npm run loop:once` 를 호출한다. 직전 실행 대비 변화만 나오므로 출력이 짧다.

에이전트 작업 규칙(권장):
1. 시작 전 `loop:once`로 기준선을 잡는다.
2. 수정 -> `loop:once` -> 새로 깨진 항목이 있으면 그것만 고친다. 같은 항목을 3번 고쳐도 안 풀리면 접근을 바꾼다.
3. 마무리 전 `npm run harness` 전체 통과 + 실화면 스모크 통과를 확인한다.
4. 푸시 전 훅(`.githooks/pre-push`)이 전체 하네스를 자동 실행한다. 새 PC에서는 `git config core.hooksPath .githooks` 한 번.

## 3. 실화면 스모크 (그룹웨어 탭에서 실행)

`scripts/live-smoke.browser.js`: 모든 메뉴 화면 전환, 오버레이 열기/닫기, 값 이상("undefined", "NaN", "[object Object]") 검사, 12px 미만 글자, 가로 넘침, GW 비서 안에 상신/결재/삭제 버튼이 없는지, 최근 앱 오류. 읽기 전용이다. 실행법은 파일 머리말 참고(백그라운드 시작 후 `window.__smoke` 폴링).

### 둘러보기로 눈으로 확인

`npm run live:demo` → <http://127.0.0.1:3220>. 그룹웨어 로그인 없이 지어낸 자료로 모든 메뉴를 띄운다. 화면·CSS를 고쳤으면 밝게·어둡게와 좁은 창(약 760px)까지 여기서 확인한다. 실제 그룹웨어 동작(원래 화면 열기, 첨부 받기)은 확인되지 않으므로 실화면 스모크를 대신하지 않는다.

## 4. 코드 그래프

- `npm run graph` 의심 목록, `npm run graph:write` 로 `docs/engineering/code-graph.md`(Mermaid 모듈 의존, 이벤트->함수 그래프) 갱신.
- 용도: 어디를 고치면 어디가 영향받는지 보기, 쓰이지 않는 처리기/죽은 코드 정리 후보 찾기, 모듈이 한쪽으로 쏠리는지 점검.
- 한계: 정밀 파서가 아니다. 문자열/주석을 지운 뒤 식별자를 읽는 방식이라 "의심 목록"이다. 동적으로 만든 함수 이름은 못 본다.

## 5. 구조 규칙

- 순수 판정 로직은 `src/live/briefing.mjs`에 두고 테스트를 붙인다(화면 코드에는 계산을 두지 않는다).
- 화면 조각(`src/live/wc/NN-*.js`)은 파일명 순으로 이어 붙는다. 새 `data-act`를 만들면 `16-events.js`에 `case`를 같이 만든다(하네스가 검사).
- 비가역 동작은 코드로 차단하고, 새 외부 주소는 허용 목록에 이유와 함께 추가한다.
